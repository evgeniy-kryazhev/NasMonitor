# Несколько виджетов

На странице «Виджет» доступны список текущих виджетов и кнопки
«Создать виджет» / «Удалить виджет». После создания выберите NAS в поле
«Источник данных виджета». Разные виджеты могут показывать разные NAS или
один и тот же NAS. Новый экземпляр появляется со смещением относительно
выбранного и в зафиксированном режиме.

Каждый экземпляр сохраняет собственные NAS, внешний вид, положение, размер
и фиксацию. Вкладки внешнего вида и расположения редактируют только выбранный
экземпляр. Переключение не теряет черновик внешности в текущем сеансе;
для сохранения на диск по-прежнему нужна кнопка «Применить внешний вид».
Выбор NAS сохраняется сразу. Состав и выбранный экземпляр восстанавливаются
после перезапуска.

Удаление закрывает только выбранное окно. Профили, системные пароли и опрос
NAS остаются доступны остальным виджетам. Хотя бы один виджет должен остаться;
удаление последнего отключено. Если профиль NAS удалён, его виджет показывает
пустой источник; другой NAS автоматически не подставляется.
Кнопка подключения на странице DSM назначает NAS текущему выбранному виджету.

## Хранение и совместимость

Каталог `%LOCALAPPDATA%/NasMonitor/DesktopSpike/widgets.json` содержит версию
схемы, список ID и выбранный ID. Первому виджету при обновлении назначается
новый ID с признаком `UsesLegacySettings`; его прежние layout.json,
appearance.json и source.json продолжают использоваться без переноса.
Каждый новый экземпляр хранит такие же три файла в `widgets/<id>/`.
Каталог не содержит секретов. При повреждении widgets.json приложение
показывает ошибку и не перезаписывает его стандартными значениями.
Настройки удалённых экземпляров остаются на диске, но исключаются из каталога
и больше не создают окон. Настройки NAS и credential IDs не меняются.

`WidgetWorkspace` владеет экземплярами, `WidgetController` — одним окном.
`WidgetMonitoringPresenter` распределяет общий кэш по независимым источникам.
`NasMonitoringCoordinator` продолжает создавать один polling loop и одну
сессию на NAS независимо от числа окон. Закрытие экземпляра снимает только
его UI-подписки. Общий арбитр жестов предотвращает одновременное перемещение
нескольких пересекающихся окон одной кнопкой мыши.

## Проверки

```powershell
dotnet build NasMonitor.slnx -c Release
dotnet test NasMonitor.slnx -c Release --no-build
./scripts/publish.ps1 -Runtime win-x64
./artifacts/NasMonitor-win-x64.exe --smoke-test
```

Smoke использует отдельный `artifacts/smoke-settings/`, тестовые NAS и
синтетические метрики. Реальные подключения не выполняются, пользовательский
каталог виджетов не изменяется. Повторный запуск проверяет восстановление
двух окон из этого каталога. Отчёт — `artifacts/smoke-report.json`, снимки —
`artifacts/ui/`.

Фактический результат на Windows build 26200: сборка без предупреждений,
87 unit-тестов прошли. Опубликованный win-x64 exe прошёл smoke с
`WidgetCount=2`, `RestoredWidgetCount=2`, `MultipleWidgetsVerified=true`.
ID обоих экземпляров до и после перезапуска совпали. Оба native host живы,
обе минимальные высоты проверены. Блокеров для Windows-сборки нет;
ручные проверки ниже остаются открытыми.

Основные изменённые файлы: `Services/WidgetWorkspace.cs`,
`Services/WidgetMonitoringPresenter.cs`, `Services/WidgetController.cs`,
`Models/WidgetInstance.cs`, `Persistence/WidgetCatalog*.cs`,
`Persistence/WidgetSettingsStore.cs`, `Views/Pages/WidgetSettingsView.axaml*`,
`Views/Windows/ManagerWindow.axaml.cs`, DI и App lifecycle.
Новые независимые проверки — `MultipleWidgetTests.cs` и `WidgetCatalogTests.cs`;
сценарии окон находятся в partial-файлах `*.SmokeTests.cs`.

| Требование | Статус |
| --- | --- |
| Независимые источники, внешний вид и геометрия | Implemented / Automated-tested |
| Общая сессия на NAS при нескольких виджетах | Automated-tested, fake provider |
| Каталог, отдельные настройки и совместимость legacy | Automated-tested |
| Создание/переключение/удаление desktop-окон Windows | Automated-tested, UI smoke |
| Несколько виджетов с реальным DSM | Unverified |
| Перетаскивание пересекающихся окон, Win+D, Explorer restart | Unverified для нескольких окон |
| Несколько окон macOS, Spaces и восстановление после сна | Unverified, отложено пользователем |

Ручная приёмка: создать два виджета, назначить разные NAS; затем один NAS обоим,
сверить метрики. Задать разные размеры и оформление, перезапустить приложение.
Переместить каждый виджет, проверить фиксацию, Win+D и перекрытие обычными
окнами. Удалить один экземпляр и убедиться, что второй продолжает обновляться.
