Windows-скриншот показывает storage 30%, статус «В сети» и остальные метрики.
Отображение заполнения на его NAS — Manually-tested пользователем; контекст
испытания — monitoring с ролью «Мониторинг системы» без administrators.
Сверка процента с DSM, точная версия/модель, другие устройства и macOS — Unverified.
Для одного тома без storagePools прямой и вложенный ответы проверены автотестами.

## Реализация

Сборщик получает CPU/RAM/сеть из обнаруженного `SYNO.Core.System.Utilization` v1
(`get`), температуру/uptime/model/firmware из `SYNO.Core.System` v1 (`info`),
тома сначала из `SYNO.Core.System` v1 (`info`, `type=storage`):
`vol_info[].name`, `used_size`, `total_size`, размеры в байтах. При недоступном
или некорректном ответе резерв — `SYNO.Storage.CGI.Storage` v1
(`method=load_info`, `action=load_info`). Успешный Info Center исключает вызов
Storage Manager. Эти Core API не имеют
публичной гарантии совместимости. Формат проверяется, совместимость с конкретным
NAS подтверждается только испытанием на нём.

Роль DSM «Мониторинг системы» документированно включает Info Center > Storage,
однако права конкретного внутреннего API зависят от DSM. Новый путь реализован
и покрыт автоматическими тестами; пользователь подтвердил отображение storage
на своём NAS в описанном выше контексте. Наличие API или успех остальных System-запросов
не доказывает разрешение на `type=storage`. Квоты папок/пользователя и ёмкость
физических дисков не используются как замена размера томов.

CPU — сумма user/system/other load, а не load average. Сеть — total.rx/tx в B/s,
с десятичными KB/MB/GB; общий счётчик не складывается с интерфейсами/bond.
Хранилище — сумма used / сумма total логических томов, не среднее процентов
и не физическая ёмкость RAID. Неизвестный/некорректный том не исключается скрытно
из агрегата. Температура системная, не средняя температура дисков. Uptime
нормализуется из часов `HHH:MM:SS`; неизвестный формат остаётся недоступным.
Данные по томам и firmware/model присутствуют в snapshot; отдельная UI-таблица
томов и графики не входят в этот срез.

Один loop и одна сессия на NAS. По умолчанию ресурсы каждые 10 секунд после
завершения предыдущего цикла; System/Storage раз в 60 секунд. Три одновременных
цикла максимум. Таймаут цикла 30 секунд, HTTP 15 секунд. После временных ошибок
backoff 20–300 секунд с jitter 0.8–1.0; ручное обновление пробуждает loop и
обновляет все группы. Шторм параллельных refresh одного NAS не создаётся.
При отказе связи snapshot остаётся в кэше со stale-состоянием, UI показывает «—».
Самостоятельно устаревают resource >35 s и slow metrics >95 s.

Профили с OS-паролем стартуют автоматически. Ошибка пароля/2FA не повторяется
автоматически; истечение сессии допускает один повторный вход из OS store.
Несохранённый пароль и OTP после входа очищаются из долговременных ссылок.
После удаления/отключения/изменения профиля старый loop завершается с logout.
Проверка соединения и мониторинг выполняют отдельные входы без необязательного
имени приложения session. Каждый logout передаёт SID соответствующего входа.

Виджет и preview используют один view. Контент задаёт минимальную высоту при
текущей ширине; выше этого минимума размер свободно меняется и сохраняется.
Старое поле AutoHeight в JSON игнорируется. Предпросмотр имеет естественную высоту.
Скрытые группы не оставляют пустых строк. На краю экрана положение корректируется
по рабочей области; если экран физически меньше контента, остаётся прокрутка.
Настройки разделены на «Внешний вид» и «Расположение» с независимой прокруткой;
источник NAS находится над вкладками. Флажки сразу меняют preview, desktop —
после применения внешности. Выбранный NAS хранится отдельно в source.json.
Страницы растягиваются по ширине и высоте окна без прежних лимитов 1000/840 DIP.
Прокручиваемая область вкладок привязана к правому и нижнему краю окна; отступ содержимого
находится внутри неё. Колонки формы/preview имеют пропорцию 2:1 с читаемым минимумом.
UI smoke проверяет правый и нижний край обеих вкладок при изменении ширины/высоты,
с допуском одного физического пикселя для fractional DPI; снимок — widget-short.png.

## Проверка на реальном NAS

1. Закрыть предыдущую версию, запустить `artifacts/NasMonitor-win-x64.exe`.
2. Создать/выбрать профиль HTTPS. Сохранить. Для автозапуска отметить сохранение
   пароля в системном хранилище. Если пароль не сохраняли, ввести его повторно
   после сохранения. Ввести актуальный OTP, если DSM требует 2FA.
3. Нажать «Подключить виджет». При редактировании сначала сохранить изменения.
   Внешний endpoint выбирается явно флажком; он действует для этой сессии,
   при перезапуске используется основной endpoint.
4. На странице «Виджет» выбрать NAS. Сопоставить CPU/RAM/total network с Resource
   Monitor DSM с учётом разного времени выборки. Хранилище сверить с логическими
   томами Storage Manager. Температуру/uptime сверить с системной информацией.
5. Недоступная метрика — «—»; hover в preview объясняет denied/unsupported/
   invalid/stale. Для минимальных прав проверить отдельную учётную запись:
   объявленный API сам по себе не подтверждает разрешение на чтение.
6. Добавить второй NAS, переключить источник; отключить сеть только у одного.
   Проверить независимость и восстановление. После обрыва текущие цифры скрыты,
   время последних успешных данных сохранено. Ручное обновление доступно на
   странице виджета и в preview; desktop pointer input зависит от locked/host.
7. Выйти из сессии на DSM: сохранённый пароль должен позволить новый вход;
   при 2FA или несохранённом пароле нужен новый явный вход. Неверный пароль
   не должен вызывать непрерывные попытки входа.
8. Отключить/удалить профиль: его опрос завершается. Перезапустить приложение:
   источник сохраняется, включённые профили с OS-паролем возобновляют опрос.
9. На вкладке «Расположение» увеличить высоту полем или resize-жестом и проверить
   сохранение размера. Уменьшить: нижняя граница равна высоте содержимого.
   На вкладке «Внешний вид» скрыть показатели: preview уменьшается сразу;
   после применения desktop можно уменьшить до нового минимума. Включить обратно:
   при необходимости окно вырастает. Проверить край экрана, DPI и перезапуск.

Не отключать TLS validation. Для self-signed сертификатов отдельный workflow
доверия ещё не реализован; их отказ является ожидаемым поведением этого среза.

## Команды и статусы

Фактический результат финальной проверки: 78/78 тестов (19 Core + 59 Connection),
сборка без предупреждений/ошибок. Опубликованы win-x64, osx-arm64, osx-x64.
Windows EXE проверен из каталога с единственным входным файлом: exit 0,
нативные библиотеки извлечены runtime, ZIP содержит один EXE.
`artifacts/single-file-verification.json` и `artifacts/smoke-report.json` содержат
результат, SHA256 и `ContentMinimumHeightVerified: true`. Отрисованные страницы
находятся в `artifacts/ui/`. Это автоматическая проверка на Windows build 26200;
реальный DSM и macOS не использовались.

```powershell
dotnet build NasMonitor.slnx -c Release
dotnet test NasMonitor.slnx -c Release
dotnet run --project src/NasMonitor.App -c Release -- --smoke-test
./scripts/publish.ps1
```
