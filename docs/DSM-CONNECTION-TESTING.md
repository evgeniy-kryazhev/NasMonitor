# Проверка подключения Synology DSM

Текущий срез реальных метрик и автовысоты: [DSM-MONITORING.md](DSM-MONITORING.md).

## Заполнение тома с делегированной ролью без administrators

1. Под администратором проверить у monitoring: приложение DSM разрешено,
   роль «Мониторинг системы» делегирована и сохранена. Группу administrators
   для этого испытания не добавлять.
2. В браузере войти именно под monitoring и открыть Информационный центр >
   Хранилище: записать, видны ли тома и их занятый/общий объём.
3. Закрыть старый NAS Monitor, запустить свежий artifacts/NasMonitor-win-x64.exe.
   Выбрать NAS, нажать «Подключить виджет», затем «Обновить метрики».
4. Сверить процент с суммой used / суммой total томов Информационного центра.
   Для одного тома результат должен совпадать с его заполнением. Никаких
   изменений томов/пулов или разрешений на общие папки не требуется.
5. Если storage снова недоступно, записать видимую строку причины и DSM-код.
   Дополнительно сообщить версию DSM и доступность раздела из пункта 2.
   Пароли, SID, OTP и токены не передавать.

Новый основной запрос: SYNO.Core.System v1 info type=storage, через обнаруженный
путь, с POST SID и заголовком X-SYNO-TOKEN. Старый load_info используется только
при неудаче основного запроса. Пользователь 2026-10-17 подтвердил работу и
показал 30% заполнения со статусом «В сети» на Windows. Это Manually-tested
для его запуска; точная DSM version/model, повторная проверка состава групп и
сверка процента с DSM остаются Unverified.

## Отсутствует только хранилище

Запустить новый Windows EXE, подключить виджет и открыть страницу «Виджет».
Если storage остаётся «—», прочитать строку под «Обновить метрики» без наведения.
Она должна показать причину хранилища, например недостаток прав с DSM-кодом.
Если сервер не вернул код, показывается доступный статус (unsupported, invalid,
unavailable). При ручном обновлении переопрашивается в том числе storage;
при обычном опросе оно кэшируется 60 секунд. Записать текст строки. Не повышать
права, не создавать пулы и не менять тома до установления причины отказа.
Один том без пула поддержан parser-тестами; фактический формат/доступность
ответа этого устройства пока Unverified.

## Повторная проверка сессии метрик после исправления CSRF

1. Закрыть прежний NAS Monitor, запустить свежий artifacts/NasMonitor-win-x64.exe
   (на macOS — обновлённый bundle соответствующей архитектуры).
2. В «Подключения DSM» выбрать NAS и нажать «Подключить виджет»; одного
   «Проверить соединение» недостаточно. При необходимости ввести пароль/OTP.
3. Открыть «Виджет», проверить выбранный источник и дождаться первого опроса.
   Записать фактические показатели и причины отсутствующих метрик.
4. Если снова появляется «Сессия истекла», записать теперь отображаемый
   числовой код DSM, не присылать пароли/OTP/SID/токены.
5. Если метрики появились, выполнить проверку соединения при работающем
   виджете и убедиться, что он продолжает обновляться после выхода probe.

CSRF-защиту и права DSM в процессе не менять. Новый транспорт передаёт
X-SYNO-TOKEN в заголовке запроса, _sid остаётся в POST body.
Результат на реальном устройстве пока Unverified.

## Повторная проверка DSM 402 после исправления session

Исправленная сборка не передаёт `session=NASMonitorProbe` или `session=NASMonitor`.
Вход использует документированный общий запрос DSM, выход — SID этого входа.

1. Для отдельного пользователя разрешить приложение DSM. При наличии роли
   делегированного администрирования «Мониторинг системы» включить её и
   подтвердить OK/сохранение. Другие роли и группу administrators автоматически
   не добавлять: минимальные права каждого используемого API ещё Unverified.
2. Закрыть старую версию NAS Monitor и запустить новую сборку из artifacts.
3. Повторить «Проверить соединение». Если пароль не сохранён, ввести его снова;
   если включена 2FA, ввести актуальный OTP. Записать стадию и код отказа.
4. При успешном входе нажать «Подключить виджет» и проверить CPU/RAM/сеть,
   температуру/uptime и тома отдельно. Успешный login не доказывает право читать их.
5. Во время активного мониторинга повторить «Проверить соединение» и убедиться,
   что завершение временной сессии не прерывает обновление виджета.

Если 402 остаётся, это не доказательство необходимости administrators. Нужно
сопоставить вход в браузере под тем же пользователем, версию DSM, сохранённые
разрешения и фактическую стадию ошибки. Пароли, OTP и SID не присылать.
Все пункты этого повторного испытания пока Unverified.

## Запуск и страницы

Windows: запустить `artifacts/NasMonitor-win-x64.exe` или извлечь один EXE из
`artifacts/NasMonitor-spike-win-x64.zip`. Имя архива пока историческое.
Слева выбрать «Виджет» или «Подключения DSM». Тема находится внизу навигации.
Под вкладками находится список сохранённых NAS; клик/Enter открывает выбранный
профиль. «Добавить NAS» закреплена внизу справа под прокручиваемой формой
и создаёт пустой черновик. Уменьшить высоту окна и проверить, что при прокрутке
формы кнопка остаётся видимой на прежнем месте.
Наличие в списке означает сохранённый профиль, а не непрерывно проверенную онлайн-сессию.
При переключении сохраняется черновик metadata, пароль/OTP очищаются,
активная проверка отменяется. Новый профиль сохраняется только кнопкой сохранения.

## Кастомизация виджета

На странице «Виджет» изменить название (до 60 символов), цвет #RRGGBB,
непрозрачность (35–100%), скругление (0–32 DIP), тему и видимые показатели.
Предпросмотр меняется сразу при вводе названия, HEX, чисел, темы и флажков.
Нажать «Применить внешний вид», чтобы сохранить значения и обновить desktop widget.
Пока HEX введён не полностью, предпросмотр сохраняет последний корректный цвет.
«Сбросить внешний вид» сохраняет стандартную внешность, не меняя NAS/координаты.
Настройки находятся рядом с layout.json в `DesktopSpike/appearance.json`.

Ручные проверки кастомизации: применить нестандартный цвет, выключить RAM,
выбрать тёмную тему виджета при светлом Manager, проверить читаемость,
перезапуск и сброс. Убедиться, что drag/resize/lock продолжают работать.
Прозрачность/скругления поверх wallpaper требуют отдельной проверки WorkerW
и AppKit; API smoke подтверждает только привязку, а PNG — Avalonia rendering.

## Первый NAS

1. Нажать «Добавить NAS». Ввести название, полный HTTPS origin DSM с портом,
   например `https://nas.example:5001`, и имя пользователя. Адрес в примере фиктивный.
2. Ввести пароль. По желанию включить «Сохранить пароль в системном хранилище»
   и нажать «Сохранить профиль». Это сохраняет профиль без сетевого входа.
3. Выбрать профиль, нажать «Проверить соединение». Если пароль не запоминался,
   ввести его непосредственно перед проверкой. Пароль/OTP после операции очищаются.
4. Если DSM требует 2FA, ввести актуальный OTP и повторить проверку. Если пароль
   не сохранён, повторно ввести и пароль. Автоматических повторов неверного входа нет.
5. Проверить стадии и успешный выход. «Авторизация подтверждена» означает только
   успешный login; ошибка capabilities/logout видна отдельно. «Права мониторинга»
   пока всегда Unverified: чтение CPU/RAM/storage в этом срезе не реализовано.

Внешний endpoint необязателен. Для его проверки явно включить соответствующий
флажок; приложение не переключается на него после ошибки основного адреса.
При изменении любого endpoint или username сохранённый пароль не переиспользуется:
введите его заново для новой конфигурации. HTTP, reverse-proxy subpaths, QuickConnect
и разрешение недоверенного сертификата в этом срезе не поддержаны.

## Ручная матрица — не выполнена на реальном NAS

| Сценарий | Ожидание | Статус |
|---|---|---|
| DS216+II и DS1821+, фактическая DSM version | Отдельно записать модель/версию/права и стадии | Unverified |
| Два профиля | Независимые IDs, адреса, секреты и проверки | Unverified (mock/storage tested) |
| Верный пароль | Login, capabilities и logout; права отдельно | Unverified |
| Неверный пароль | Ошибка без повторов и без утечки пароля | Unverified (mock tested) |
| 2FA required / неверный / верный OTP | Запрос кода и повтор вручную | Unverified (mock errors tested) |
| Неадминистратор | Фактические ограничения прав записаны, не выданы за успех | Unverified |
| Выключенный NAS / неверное имя / timeout | Соответствующая стадия и возможность отмены | Unverified |
| Неверный TLS/hostname/истёкший сертификат | Вход не выполняется | Unverified (local self-signed reject tested) |
| Сохранение/редактирование/отключение/удаление | Сохраняются metadata; удаляется только соответствующий OS-secret | Unverified (storage tested) |
| Перезапуск с запомненным паролем | Проверка без повторного ввода; JSON без password/OTP/SID | Unverified |
| Переход на другую страницу во время проверки | Отмена, cleanup logout, поля секретов очищены | Unverified (cancellation/navigation logic tested) |
| Semi light/dark/system | Обе страницы читаемы, навигация и widget работают | Unverified (Windows launch/render tested) |
| macOS Keychain и AppKit | Проверка на arm64/x64 отдельно | Unverified / отложено пользователем |

Профили: `LocalApplicationData/NasMonitor/profiles.json`, SchemaVersion=1.
На Windows обычно `%LOCALAPPDATA%/NasMonitor/profiles.json`.
Credential Manager: generic items `NASMonitor/DSM/<opaque UUID>`.
Keychain: service `NASMonitor.DSM`, account — opaque UUID.
Для доверенного self-signed NAS пока нужен корректный доверенный сертификат с
подходящим hostname; проверка не предлагает отключение TLS validation.

## Воспроизведение проверок

```powershell
dotnet build NasMonitor.slnx -c Release
dotnet test NasMonitor.slnx -c Release
dotnet run --project src/NasMonitor.App -c Release -- --smoke-test
./scripts/publish.ps1
```

Тесты используют только synthetic credentials, mocked HTTP и локальный TLS fixture.
WindowsIntegration пишет временный synthetic OS-secret под случайным UUID и удаляет
его в finally. На другой ОС этот тест inconclusive. macOS Keychain ещё не запускался.
Smoke не обращается к NAS, переключает обе страницы/темы и сохраняет render PNG
в `artifacts/ui/`. JSON host evidence — `artifacts/smoke-report.json`.
`widget-custom.png` использует временную synthetic внешность для проверки
отдельной темы/выбора метрик, затем восстанавливает загруженные значения без записи.
Smoke дополнительно меняет реальные поля формы, проверяет живое обновление и
изоляцию от сохранённой внешности, а также выравнивание/максимальную ширину страниц
на окне 1500 DIP (`widget-wide.png`, `connections-wide.png`).
