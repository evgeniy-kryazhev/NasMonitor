# Техническое задание NAS Monitor — V1

## 1. Назначение и ограничения
Кроссплатформенный аналог части возможностей NAS Pro, с приоритетом постоянного мониторинга нескольких NAS на рабочем столе Windows и macOS. Не копировать UI или исходный код NAS Pro. Первую версию ограничить Synology DSM, но спроектировать API для дальнейшего добавления QNAP/TrueNAS.

## 2. Режим рабочего стола — ОБЯЗАТЕЛЬНО
- Виджеты должны находиться за обычными окнами и не становиться поверх приложений при получении фокуса.
- При показе рабочего стола виджеты остаются видны; поведение относительно иконок рабочего стола и окон Finder/Explorer исследовать и явно документировать.
- Положение и размер сохраняются; виджеты не исчезают навсегда после перезапуска shell, смены разрешения, DPI или переподключения дисплеев.
- Поддержать перемещение, resize и lock, при наличии технически надёжного механизма ввода.
- Не показывать виджеты отдельными кнопками на панели задач/Dock, когда это допустимо ОС.
- Два и более виджета, независимые размеры и позиции; разные мониторы.
- Не выдавать плавающее окно с `Topmost=false` за выполнение desktop-режима.
- При невозможности обеспечить это через стабильные публичные API: зафиксировать ограничение, реализовать диагностируемый прототип и предложить архитектурные варианты; не менять требование молча.

## 3. Совместимость
- Windows 10/11 x64; macOS arm64 и x64.
- .NET 10 LTS, Avalonia UI 11.x stable.
- В первой версии тестировать Synology DS216+II и DS1821+ (DSM 7.1+ заявленный ориентир; конкретные версии узнаём на подключении).

## 4. Подключение NAS
- Создать, редактировать, удалять, временно отключать профиль NAS.
- Поля: название, провайдер, локальный адрес/IP или hostname, внешний адрес (опционально), порт, HTTPS, имя пользователя, учётные данные.
- Поддержать разные endpoint-и и предсказуемую политику переключения между локальным/внешним адресами; не обходить сертификаты автоматически.
- `Test Connection` с отдельными стадиями: DNS/TCP, TLS, API discovery, authentication, capabilities, minimum permissions.
- Поддержать 2FA там, где это позволяет официально доступный механизм DSM. Не сохранять OTP.
- QuickConnect: отдельное исследование, не трактовать ID как простой DNS; не обещать поддержку без проверки.
- Опциональное обнаружение устройств LAN после проверки методов и разрешений.

## 5. Набор метрик
Обязательные при наличии API и прав: доступность NAS, модель, DSM version, CPU%, RAM%, interface rx/tx rates, тома (used/total/%), last seen, uptime если предоставляется.
Желательные: температура, диск health, storage pool, RAID, SMART краткий статус.
Каждая метрика имеет value, collectedAt, availability status и при необходимости provenance/capability; `Unavailable`, `PermissionDenied`, `Stale` никогда не превращать в 0.

## 6. Виджеты
- Размеры: Mini / Compact / Detailed; настраиваемый набор показателей.
- Виджет на один NAS или агрегированный виджет нескольких NAS.
- Online/Offline/Degraded/AuthenticationRequired/Unsupported/PermissionDenied/Unknown; таймстамп последней валидной метрики.
- Темы светлая/тёмная/системная; opacity, corner radius, locked, manual refresh; настройки для каждого виджета.
- Один клик может открыть DSM в системном браузере через настроенный URL (внимательно с TLS/адресом).
- Контекстные действия: настройка, открыть DSM, обновить, зафиксировать расположение, скрыть.
- Системный трей/меню-бар для открытия Manager и управления виджетами.

## 7. Опрос
- По умолчанию 10 с для динамических метрик; 60-300 с для статичных параметров (конфигурируемо, адаптировать под документированные ограничения API).
- Один poller на NAS, несколько подписчиков; таймаут, bounded concurrency, retry с exponential backoff+jitter, отмена и корректное завершение.
- После сна/пробуждения и восстановления сети возобновлять опрос без штормов запросов.
- История последних метрик в памяти; долгая история только как отдельная функциональность.

## 8. Хранение
- Профили и конфигурация — SQLite или JSON с явной схемой и миграциями; секреты только Windows Credential Manager / macOS Keychain.
- Связь профиля с секретом через opaque credential identifier. Никаких токенов в логах, дампах и sample configs.

## 9. Функциональные требования UI
- Главное окно: список NAS, карточки сводки, детали, графики, настройки и управление виджетами.
- Форма подключения с тестированием и обработкой ошибок.
- RU интерфейс, закладка под EN.
- Ясное сообщение при отказе соединения: сертификат, неверный пароль, 2FA, недостаток прав, недоступность API, network timeout.

## 10. Нефункциональные требования
- Не требовать admin/root по умолчанию. Не инсталлировать background system services без причины.
- Надёжная работа при offline; корректное закрытие всех polling tasks; минимальное idle CPU/память.
- Высокое DPI, несколько мониторов, системные темы, доступность текста.
- Автотесты доменной логики, mock DSM HTTP, отдельный manual OS test plan.

## 11. Вне V1
- QNAP и TrueNAS провайдеры, Docker, виртуализация, резервные копии, пользовательские операции администрирования, выключение NAS, Download Station, файловый менеджер, QuickConnect до исследования.

## 12. Приёмка
1. Демонстрация desktop-level виджета на Windows и macOS со скринкастом или фактической проверкой; работоспособность за обычными окнами доказана. Если не выполнено — соответствующая платформа остаётся незавершённой.
2. Установка и запуск на Win x64, macOS arm64/x64 (каждая подтверждённая/неподтверждённая отдельно).
3. Подключение двух NAS с независимыми профилями, работа при выключении одного.
4. Проверка корректного различия между 0%, offline, missing data и denied.
5. Сохранение позиции после перезапуска приложения; состояние после restart shell и смены дисплея проверено на целевой платформе.
6. Доказательство, что секреты не попадают в JSON/SQLite/logs и TLS-валидация по умолчанию включена.
7. `dotnet build`, `dotnet test`, инструкции запуска и отчёт о ручных тестах.
