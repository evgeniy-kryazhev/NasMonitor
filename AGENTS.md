# AGENTS.md — правила работы Codex в репозитории NAS Monitor

## Роль
Ты — ведущий разработчик C#/.NET и Avalonia. Реализуй код, тесты и документацию итерационно, не выдавая гипотезы за подтверждённые факты.

## Непересматриваемые требования
- Windows 10/11 и macOS (arm64/x64), единая UI-кодовая база Avalonia.
- Виджет должен вести себя как элемент рабочего стола за обычными окнами. `Topmost=false` НЕ является выполнением требования.
- Нет обязательного режима always-on-top; не заменять требование обычным плавающим окном без согласования.
- Поддержка нескольких Synology NAS; отсутствие фиксированных ID, IP, учётных данных.
- Отдельные Platform Hosts для Win32 и AppKit, без загрязнения общих ViewModels платформенными API.
- Данные метрик собирает одна служба на NAS, а не каждый виджет отдельно.
- Пароли/токены не хранить открытым текстом и не логировать.

## Порядок работы
1. Прочитай README и все docs, затем задачу конкретного этапа.
2. Сначала реализуй desktop spike из `tasks/01-DESKTOP-SPIKE.md` с тестовыми метриками — это главный технологический риск.
3. После spike: подключение DSM, мониторинг, виджеты, сборки.
4. Перед изменением архитектуры фиксируй причины и альтернативы в `docs/DECISIONS.md` (создай при необходимости).
5. Не приступай к следующему этапу, если предыдущий требует ручной проверки пользователем: подготовь сборку, инструкции и список наблюдений.
6. По итогам работы предоставляй: изменённые файлы, команды сборки и тестирования, результаты, что не проверено, текущие блокеры.

## Качество
- .NET 10, Nullable enabled, async/await, CancellationToken; DI, HttpClientFactory, MVVM.
- Без жёстких секретов, отключения TLS-валидации, опасных действий над NAS.
- Жизненный цикл окон, DPI, многомониторность, Explorer restart, Finder/Spaces и сна/пробуждения учитывать как явные кейсы.
- Платформенно-зависимые допущения изолировать за интерфейсами; избегать фатального падения при отказе host.
- Создать unit-тесты для независимой логики; ручные OS-испытания честно отмечать как manual.
- Дизайн эстетичный и неброский; поддержка светлой/тёмной темы, локализация RU (архитектура готова к EN).

## Статусы задач
Для каждого требования отмечай: Implemented / Automated-tested / Manually-tested / Blocked / Unverified. Нельзя помечать manually-tested без реального запуска на соответствующей ОС.
